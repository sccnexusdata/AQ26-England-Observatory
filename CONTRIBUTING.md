# Contributing to AQ26

AQ26 welcomes evidence-based scrutiny, reproducibility checks, documentation improvements and scientifically justified corrections.

## Scientific issues

When reporting a possible scientific error, please include where possible:

- the affected file/page and metric;
- observation or reporting period;
- source/network/station identifier;
- pollutant or variable;
- units and averaging period;
- expected denominator and observed denominator;
- quality or ratification state;
- the primary source or reproducible calculation supporting the correction.

Please distinguish a factual/data reconciliation error from a different interpretation of the same evidence.

## Claims and attribution

Do not propose source attribution from proximity, temporal coincidence or a single model/satellite/monitoring source alone. Stronger interpretations should explicitly test plausible competing explanations and preserve uncertainty.

## Code and reproducibility

Public-side validation code should remain deterministic, small and dependency-light. Changes that alter scientific output definitions should include regression tests and a clear explanation of the scientific consequence.

## Security and sensitive information

Do not post passwords, API keys, private keys, credentials, protected internal logs or other sensitive material in issues or pull requests. See `SECURITY.md`.

## Licensing

Do not add third-party datasets or substantial extracts unless their redistribution terms have been checked and recorded. Linking to an authoritative source does not automatically grant republication rights.
